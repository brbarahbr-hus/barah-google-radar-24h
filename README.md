# BARAH Google Radar 24H

نسخة GitHub Actions + Pages لمختارات بارعة اليومية. أُعدت من حزمة الرادار السابقة دون الحاجة إلى Cloudflare أو خادم مدفوع. التحديث مجدول عند 05:00 بتوقيت الرياض، وقد يتأخر بدء GitHub Actions.

## الحالة

كود التشغيل جاهز للاختبار. مزامنة المصادر والنشر متوقفان افتراضيًا حتى إعداد المتغيرات أدناه. لا يوجد ملف منتجات منشور أو تفعيل في قالب سلة. تشغيل اختبارات الكود وحده لا يعني اتصال المصادر.

## إعداد قراءة المصادر

من Settings → Secrets and variables → Actions أضف:

| النوع | الاسم | الغرض |
| --- | --- | --- |
| Secret | `SALLA_ACCESS_TOKEN` | رمز صادر لتطبيق سلة مستقل بصلاحية `products.read`؛ لا تستخدم رمز موصل ChatGPT |
| Secret | `WINDSOR_API_KEY` | مفتاح Windsor المتاح في حسابك الحالي؛ لا يتضمن المشروع إنشاء اشتراك جديد |
| Variable | `ADS_ACCOUNT_ID` | حساب Google Ads الذي يعيده Windsor |
| Variable | `ADS_CAMPAIGN_ID` | اختياري: معرف حملة PMAX الرياض، وإلا تُطابق الحملة باسم الرياض وPMAX |
| Variable | `GA4_ACCOUNT_ID` | اختياري: حساب/خاصية GA4 التي يعيدها Windsor |
| Variable | `SALLA_PAID_ORDERS_ENABLED` | اختياري `true` عند منح `orders.read` أيضًا؛ إن تعذّر توثيق الدفع لا تحتسب المبيعات |
| Variable | `EXCLUDED_PRODUCT_IDS` | اختياري: معرفات إضافية مفصولة بفواصل لاستبعادها من القسم |
| Variable | `RADAR_SYNC_ENABLED` | `true` يسمح بالقراءة والاختبار المجدول أو اليدوي |
| Variable | `RADAR_PUBLISH_ENABLED` | اتركه `false` أثناء الاختبار؛ `true` يسمح بالنشر بعد نجاح اختبارين حقيقيين |

الأسرار لا تُكتب في Git أو JSON أو السجلات. بيانات العملاء والطلبات الخام لا تُحفظ. يقرأ التنفيذ واجهات سلة/Windsor فقط ولا يعدل المنتجات أو الحملات.

**تجديد سلة:** هذه النسخة لا تستهلك refresh token ولا تجدده تلقائيًا. رمز سلة ينتهي بعد نحو 14 يومًا ويجب تحديث Secret قبل انتهائه. ربط ChatGPT بسلة لا يمنح GitHub رمزًا قابلًا للنقل. التجديد الدائم يحتاج إعداد OAuth مستقل ومخزن آمن لرموز التجديد أحادية الاستخدام؛ لم يُفعّل هنا.

## التحقق ثم النشر

1. أضف مفاتيح القراءة والمتغيرات، واجعل `RADAR_SYNC_ENABLED=true` و`RADAR_PUBLISH_ENABLED=false`.
2. من Actions شغّل **BARAH radar daily sync → Run workflow** مرتين. يلزم نجاح قراءات فعلية ومراجعة 6 منتجات مؤهلة على الأقل في كل تشغيل. اختبارات البيانات المصطنعة لا تُحتسب.
3. يتطلب كل منتج مخزونًا لا يقل عن 3، وسعرًا موجبًا، ووصفًا، وصورة ورابطًا سليمين، وإشارة اهتمام فعلية. تمنع الخوارزمية التكرار في الرئيسية وتختار منتجين كحد أقصى لكل فئة.
4. بعد نجاح الاختبارين خلال 72 ساعة، اختر Settings → Pages → Source: **GitHub Actions** ثم اضبط `RADAR_PUBLISH_ENABLED=true` وشغّل التحديث. لا تفعّل الواجهة قبل التحقق من JSON ورؤوس CORS والصور على الرابط الحي.
5. الرابط المتوقع بعد نجاح النشر، وليس رابطًا نشطًا الآن:
   `https://brbarahbr-hus.github.io/barah-google-radar-24h/api/radar/latest.json`
6. بعد التحقق من الرابط، اربطه بمتغير `window.BARAH_RADAR_24H_FEED_URL` في الواجهة الموجودة. ملفا `storefront/` للمراجعة فقط؛ هذا المستودع لا يعدّل كود سلة.

يحفظ `state/validation.json` عدد المنتجات والتوقيت وبصمة الكود والإعدادات فقط. تغيير الكود أو نطاق الحسابات يصفر أهلية الاختبارين. عند فشل المصدر أو نقص المنتجات لا تُنشر نسخة بديلة؛ تبقى آخر نسخة منشورة وتتعامل الواجهة مع تقادمها: وصف محايد بعد 24 ساعة وإخفاء بعد 72 ساعة. Pages استضافة ثابتة ولا يوفر API إبطالًا فوريًا عند تغير المخزون.

المصادر الحالية: إعلانات حملة PMAX الرياض، GA4 عند الربط، وكتالوج سلة. لا يدّعي هذا التنفيذ قياس حجم البحث في السعودية؛ Search Console وKeyword Planner وTrends والربحية غير متصلة ويصرح بها JSON.
